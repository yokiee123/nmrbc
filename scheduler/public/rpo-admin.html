RPO Notifications

New published events and amendments to published events. Regular AM/PM swaps do not trigger RPO email.

Administrator login

RPO maker

The scheduler currently uses Confirmed as Published and Planned as Draft. Existing confirmed events are recorded as a baseline during installation and will not generate retroactive mail. Changes to published events are tracked thereafter. Changes to an already-published event reverted to Planned will still notify the maker.

Saving settings does not itself send a test. Emails require deployment and scheduling of the RPO worker. If the worker is not running, pending messages remain in the queue.

Amendment and delivery history

Accepted means Gmail accepted the message, not that it reached the inbox. An uncertain result is never retried automatically to avoid duplicates. Use the latest event revision when preparing an RPO.
